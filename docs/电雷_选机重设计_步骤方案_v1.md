# 《电雷》选机重设计：步骤方案 v1

状态：**六项已答复，#69 已按第 3 题拆掉被否画面。** 本文仍是后面 G1–G4 的步骤。这轮不出图、不重画机体、不加调色板颜色、不合并。

Yoan 的原话意思：选机界面「实在太丑了，离我期望的差距太大」，**选机 UI 和飞机造型都不满意**，倾向重新拆步骤，**先从 UI 图开始确认**。本文默认按这个顺序走。

本次被否决的范围：

- 选机画面的样子（`src/game/ui/shipSelect.ts` 的画法）。
- Mandy、Jason 的局内像素（`src/game/art/shipSprites.ts`）。

本次**没有**被否决、方案里也不动的：Eagle 的像素，三机手感数字（`shipDefs.ts` 的移速、判定、射速、伤害、弹速、弹形），选机在进战流程里的位置，交接 / Retry 沿用机体。若 Yoan 认为这些也要重开，在 §8 的问题里说。

---

## 1. 一句话结论

#69 是「先把文字和数字确认，再由程序按文字去画」。Yoan 确认的是一段文字说明、一张 ASCII 线框和一张高清气氛图，**从来没有看到过一张 360×640 的选机画面，也没有看到过一张局内尺寸的 Mandy / Jason 像素图**，代码就已经写完了。结果是：画面照着文字做对了，但不好看；像素照着规格做对了，但和他确认的气氛图不是同一架飞机。

下一轮把顺序反过来：**先看到图，确认图，图就是规格；代码只照图做。**

## 2. 复盘：选机 UI 哪里不对

### 2.1 把合金弹头 3 的「竖栏」改成了「横行」

合金弹头 3 的 SOLDIER SELECT 是四个**并排的竖栏**，每一栏又高又窄，人物从栏底一直站到栏顶。#69 把它改成了三条**横向的行**（每行 328×156）。这样一改，画面就从「站成一排的角色」变成了「设置页的列表」：左边一块小方井，右边三行小字，三行长得一样。

竖屏其实放得下三个竖栏：360 宽减去边距，每栏约 104–110 宽、300 以上高。合金弹头的版式在竖屏上可以保留，#69 没有试。

### 2.2 禁止单独绘制立绘，等于拿掉了参考图最出彩的部分

参考图里最吸引人的是两件事：**选中的角色是全彩、会动的**，**没选中的是大幅灰色特写**。那几张特写都是专门画的大图。

#69 为了「预览就是局内帧，不另画立绘」，把灰色特写做成了「局内平飞帧上半截 55%，放大 4 倍，换成灰阶」。Eagle 的上半截只有 28×18 像素，放大 4 倍以后是一块 112×72 的灰色马赛克，看不出是机头，也看不出是哪架飞机。原则本身是对的（防止确认一张图、运行时却是另一张），但用错了地方：它保护的是局内精灵，却把选机画面的表现力一起锁死了。

### 2.3 主角太小，空的地方太多

- 选中的飞机放大 3 倍，Eagle 是 84×96，Jason 只有 66×78，放在 132×132 的井里。整屏 640 高，选中机的高度只占 12%–17%。
- 每一行除了这块井，剩下的是 156×128 的深色区域，只写了三行 12–13 号系统字。
- 底下是半透明黑罩，罩着标题后面的 attract。没有选机自己的背景（机库、甲板、发射架都没有），所以看起来像暂停菜单。

### 2.4 用的是调试面板的画法，不是这个游戏已经立住的 UI 风格

- 标题牌、名字牌、井都是 `DARK_GRAY` 平涂加 1 像素描边，四角各点 1 个像素当铆钉。放到手机上，这些铆钉和描边基本看不出来。
- 按钮直接用了 `drawButton`（半透明填充加 1–2 像素青边），和现在标题页一样薄。Yoan 给的首页参考是厚实的斜面按钮（蓝色 START、灰色 SETTINGS）、带描边的像素大字、金色 HI-SCORE；战斗参考的 HUD 也是粗字、彩色标签。#69 两边都没对上。
- 「选择机体」用的是 18 号系统字，不是像素字。合金弹头的标题是立体金属字，这一点完全没体现。
- 黄黑警示条只有 8 像素高，放在井底，几乎看不到。

### 2.5 对比不足

Mandy 的外缘是 `SHADOW` `#1a1a2e`，选机井的底色也是 `SHADOW` `#1a1a2e`。黑飞翼的边缘和背景是同一个色号，在选机画面里 Mandy 就是黑底上的一块黑。

### 2.6 没有比较信息

三架飞机的差别（速度、火力、体型）只写在小字里。参考图和同类游戏通常有能力条或者大号的关键词，一眼就能比较。#69 没有。

## 3. 复盘：机体造型哪里不对

这部分按实际栅格出来的平飞帧（第 5 帧）统计，不是按文档描述。

### 3.1 气氛图和像素图不是同一架飞机

Yoan 确认的气氛图（`ships-v3-compare`、`mandy-v3-sheet`、`jason-v2-sheet`）里，每架飞机大约 150–400 像素宽，有几十级明暗、面板线、铆钉和高光。代码只能在 32×36 和 22×26 的画布里，用几个半宽公式（`mandyHalf`、`jasonHalf`、`jasonWing`）去近似。确认的是一张图，进代码的是另一张，中间没有任何一步让 Yoan 看到「缩成局内尺寸以后长什么样」。

造型文档 §6 写了「验收对着栅格出来的平飞像素」，但这一步排在代码之后，所以实际上没有起到门禁作用。

### 3.2 Mandy

| 项 | 气氛图 | #69 像素 |
|---|---|---|
| 外形 | B-2 式飞翼：宽远大于高（约 2.2 : 1），后缘是锯齿 / W 形，两台发动机舱鼓出 | 32×36，宽和高差不多。外轮廓是一个六边形：上尖、腰部贴满画布、下面收成平底。没有锯齿后缘 |
| 明暗 | 炭灰为主，有高光面、面板线、舱门、亮边 | 共 7 个色号。纯 `BLACK` 占 440 / 808 个像素（54%）。没有受光面 |
| 中线 | 一条有结构的机脊和弹舱 | 一条 6 像素宽、从第 11 行一直拉到第 26 行的竖条（`DARK_GRAY` 加 `MEDIUM_GRAY` 中缝），像一条路 |
| 亮点 | 青色座舱、喷口 | 青色只有 12 个像素 |
| 发动机 | 两个外凸的舱，尾端明显 | 两段短竖条嵌在轮廓里，从外面看不出来 |

所以 Mandy 看起来不是「黑飞翼轰炸机」，而是「一块黑色的盾牌」。

另外，32×36 这个画布本身就装不下气氛图的比例。飞翼的识别点就是又宽又扁，竖长的画布做不出来。画布尺寸是在造型确认之前定的（手感题 3–5 的 A），这个顺序是错的。

### 3.3 Jason

| 项 | 气氛图 | #69 像素 |
|---|---|---|
| 主色 | 紫色机身为主，金色是包边和脊线 | 金色像素（`PLAYER_GOLD` 108 + `PLAYER_GOLD_LIGHT` 28 = 136）比紫色（`PLAYER_PURPLE` 68 + `PLAYER_PURPLE_MID` 22 = 90）还多，一圈金描边吃掉了轮廓，远看是一块金色 |
| 外形 | 尖头、前翼（鸭翼）、主翼后掠、两片尾翼，轮廓有好几层 | 一根细机身加一对梯形翼。没有鸭翼，没有尾翼 |
| 色阶 | 紫有三四级，金有两三级，深色座舱 | 只有 5 个色号，座舱 4 个 `BLACK` 像素 |
| 尺寸 | 和 Eagle 差不多大 | 22×26，面积约为 Eagle 的 64%。细节放不进去 |

Jason 要表达的是「小、快」。写这段复盘时靠的是判定 2.0 和当时的移速 420，画布不一定要缩那么多。2026-11-04 Yoan 改标度之后移速是 336，判定仍是 2.0。

### 3.4 和 Eagle 对比

Eagle 是同一套几何栅格方法做出来的，但它用了 14 个色号：白、浅白、青四级、蓝、灰三级、红两级，还有一圈 1 像素的 `PLAYER_DARK_CYAN` 外描边。这一圈亮边让它在任何地图上都能跳出来。Mandy 和 Jason 都没有对应的亮边，色阶也只有 Eagle 的一半。

| | Eagle | Mandy（#69） | Jason（#69） |
|---|---|---|---|
| 画布 | 28×32 | 32×36 | 22×26 |
| 色号数 | 14 | 7 | 5 |
| 最暗色占比 | 低 | `BLACK` 54% | — |
| 外描边 | 亮青，和所有地图都拉得开 | `DARK_GRAY`，和深色底几乎同色 | 金，和机身同一色相，吃掉轮廓 |

### 3.5 方法上的问题

用半宽公式生成平飞帧，好处是侧倾 11 帧可以自动算出来。坏处是每一行都是一段光滑的曲线，画不出锯齿后缘、鸭翼、尾翼这些「断开的」结构，也很难手动放高光点。Eagle 能做好，是因为它本来就是简单的后掠翼战斗机。Mandy 和 Jason 的识别点恰好都是公式最难表达的部分。

## 4. 复盘：流程

1. **确认的东西不对。** 确认的是文字、坐标表和 ASCII 线框。文字写对了不等于好看，Yoan 看不到成品就没法判断。
2. **确认的东西和要做的东西不是同一种东西。** 气氛图是高清插画，局内是 30 像素的调色板像素。两者之间缺一张「局内尺寸的像素稿」。
3. **规格定得太早。** 画布尺寸、预览倍数这些数字在看到图之前就锁了，后来的造型只能硬塞进这些数字里。
4. **UI 和造型绑在同一个 PR 里一次交付。** 两边都不满意时，没法分开改。

---

## 5. 新流程：四道门

默认按 Yoan 的想法：**UI 图 → 机型像素 → 合成 → 写代码**。每道门都要拿到 Yoan 的明确答复才往下走。上一道门没过，下一道门不开工。

| 门 | 名称 | Yoan 看到什么 | 「确认」的意思 | 这一步不能进代码的东西 |
|---|---|---|---|---|
| G1 | 选机 UI 稿 | 360×640 的整屏选机图，用 Eagle 的真实像素和 Mandy / Jason 的占位剪影（灰色块，标注「占位」）。至少给 2–3 个布局方向，最后收敛成一张 | 版式、比例、背景、牌子、按钮、字的风格、选中 / 未选中怎么区分、能力条，这些都按这张图做。图上的尺寸量出来就是规格 | 不改 `shipSelect.ts`，不改 `widgets.ts`，不新增 UI 素材文件 |
| G2 | 机型像素稿 | Mandy、Jason 的**局内尺寸像素**。分三小步：① 纯剪影（单色）和 Eagle 剪影并排；② 上色后的平飞帧；③ 侧倾第 5 档。每一步都同时给 1 倍、3 倍，以及放在 陆地A / 河流A / 海面B 背景上的样子 | 确认的那一份调色板索引数组，就是以后进代码的那一份，一个像素都不改 | 不改 `shipSprites.ts`，不改调色板，不改 `shipDefs.ts` 的画布尺寸 |
| G3 | 合成稿 | G1 的画面换上 G2 的真像素，再加一张局内截图式的合成图（飞机在地图上、带敌弹和 HUD） | 两边放在一起也成立。这张图就是验收图 | 还是不写代码 |
| G4 | 进代码 | 在 #69 上提交。运行截图逐项对照 G3 | Yoan 回「合并」 | — |

规则：

- 每道门交付的是图，不是文字说明。文字只用来标注图。
- G1 期间，若 Yoan 改了版式，G1 重出图，不带到 G2 里一起改。
- G2 期间，若 Yoan 要的轮廓装不进当前画布，就把画布尺寸作为 G2 的一部分重新提出来。判定半径和移速不跟着画布改。
- 进代码以后，G2 那一份像素用测试锁住（逐字节比对或哈希）。改一个像素就要重新过 G2。

## 6. G1：选机 UI 稿怎么做

### 6.1 三种做法

**做法 A：`GenerateImage` 出整屏效果图。**
按 360×640 的比例出 2–3 张不同布局的选机图，放在 Yoan 给的首页和战斗参考旁边。

- 好处：最快，最容易看出「感觉对不对」。参考图的风格可以直接带进来。
- 坏处：生成图不认 48 色调色板，字和像素都不准，比例也会飘。确认以后程序还是要「照着图仿」，又回到 #69 的老问题。只能当方向稿。

**做法 B：Canvas 交互稿（推荐作为确认物）。**
写一个独立的 Canvas 页面（不进游戏仓库的 `src/`），用逻辑分辨率 360×640、最近邻放大、调色板里的颜色，把 Eagle 的真实像素数据贴进去，Mandy / Jason 先用占位剪影。可以点三架切换，可以看选中和未选中两种状态，也可以切换 1 倍 / 2 倍 / 3 倍 显示。

- 好处：像素、颜色、尺寸都是真的。Yoan 看到的就是手机上会出现的样子。确认以后，页面里的每个矩形和颜色就是规格，程序抄过去不会走样。
- 坏处：第一张稿比 A 慢。气氛和质感（金属、光效）要一笔一笔画出来，不能靠模型发挥。

**做法 C：和合金弹头 3 的那一帧并排的标注线框。**
把合金弹头 3 的 SOLDIER SELECT 画成线框，旁边是电雷的竖屏线框，一块对一块标出来：哪块保留、哪块改掉。

- 好处：最直接地回答「哪里像合金弹头」。
- 坏处：线框不好看也不难看，没法回答「丑不丑」。#69 已经证明光有线框不够。

### 6.2 推荐

**先 A 后 B，C 作为 A 的附注。**

1. 第一轮用 A 出 3 个布局方向（见 §6.3），每张旁边附一小块 C 式的对照说明。Yoan 只选方向，不确认细节。
2. 第二轮用 B 把选中的方向做成真像素稿，这一张才是 G1 的确认物。
3. B 稿确认以后，把里面的尺寸、颜色、字号写回 `docs/电雷_选机UI设计_v2.md`，替换 v1。

理由：Yoan 这次的不满主要是「感觉」，A 最快能对上感觉；但只有 B 能保证「确认的就是运行时的」。两步都走，各管一件事。

### 6.3 布局方向（G1 第一轮的候选，不是定稿）

- **L1 三立柱（最接近合金弹头 3）。** 三个竖栏并排，每栏约 108 宽、360–400 高，铆钉金属框。选中的那一栏是全彩飞机，带尾焰和慢侧倾，底部有醒目的黄黑警示条；另外两栏是同一架飞机的灰色全身（不是裁一半）。每栏底下有金属名字牌。上方是立体的「选择机体」铭牌，下方是能力条和确认按钮。
- **L2 机库大图 + 底部三卡。** 上面约六成是机库或航母甲板的背景，选中的飞机放大到 4–5 倍，停在发射架上；旁边是名字牌、身份和三条能力条。下面一排三张小卡，可以点着切换，未选中的卡片是灰色。
- **L3 单机全屏轮播。** 一次只显示一架，占满屏幕，左右滑动切换，底下三个圆点。最有冲击力，但和合金弹头的「一排人站在一起」差得最远。

建议 G1 第一轮三个都出图，推荐 L1 或 L2。L1 最贴合 Yoan 点名的合金弹头 3；L2 更适合竖屏，飞机也最大。

### 6.4 UI 稿必须体现的东西

这些写在 G1 的需求里，A 和 B 两轮都要有：

- 有自己的背景（机库、甲板或带光效的金属底），不是黑罩盖住 attract。
- 牌子和按钮至少三级明暗（亮边、面、暗边）加 2 像素外框，对齐首页参考的厚按钮。
- 标题「选择机体」和三个英文名用像素字。做法是把这几个字手绘成调色板精灵，不新增字体文件（规则见 §8 问题 5）。
- 选中和未选中区别要大：全彩、会动、有尾焰、有警示条，对比灰色、静止。
- 有能力条：速度、火力、机体大小，数值来自 `shipDefs.ts`，不另编。
- 按钮和三个可点区域都不小于 44×44。

## 7. G2：机型像素怎么确认

核心目标：**不能再「确认一张图，再用代码画出另一张」。**

### 7.1 四种做法

**做法 A：先确认高清气氛图，再写公式去近似（#69 的做法）。**
已经证明不行，不再用。

**做法 B：手点局内尺寸像素（推荐）。**
直接在目标画布上，用调色板索引一格一格点出来，存成和其它精灵一样的索引字符串。Yoan 看的是这一份，进代码的也是这一份。

- 好处：确认物就是运行时数据，不会走样。能画出锯齿后缘、鸭翼、尾翼、单点高光这些公式很难画的东西。
- 坏处：侧倾 11 帧不能再自动算。右倾 5 档要手画（左倾仍然镜像），每架 6 帧，两架共 12 帧。

**做法 C：继续用几何公式，反复改到满意。**
每改一次就把栅格结果给 Yoan 看。

- 好处：侧倾仍然自动生成，和 Eagle 同一套方法。
- 坏处：#69 已经看出公式画不出这两架的识别点。迭代次数不可控。

**做法 D：用生成图缩小、量化到调色板，当作起稿。**
把确认过的气氛图缩到目标尺寸，映射到 48 色（加上新增色），得到一张粗稿，再手工清理。

- 好处：起点和气氛图的比例、配色一致，不用从零开始。
- 坏处：直接缩小会糊成一团，必须手工重画。只能当底稿，不能当确认物。

### 7.2 推荐

**B 为主，D 作为起稿。** 分三小步，每一步都要 Yoan 回复：

1. **剪影门。** 每架一张纯单色剪影，和 Eagle 剪影并排，1 倍和 3 倍各一张。只看轮廓。Mandy 要一眼是「宽扁的飞翼加锯齿后缘」，Jason 要一眼是「带鸭翼和双尾翼的小战斗机」。这一步同时决定画布尺寸。
2. **上色门。** 在确认的剪影上上色。给出色号用量表（每种色号多少像素），并放在 陆地A / 河流A / 海面B / 选机背景 四种底色上。
3. **侧倾门。** 先给右倾第 5 档（最深）和第 2–3 档，确认以后再补全其余各档。镜像和尾焰喷口位置一起给。
