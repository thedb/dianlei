## 2. 三机数值

相对 Eagle 的手感目标：

- **Eagle**：维持现状。速度、判定、火力取中。
- **Mandy（轰炸机）**：模型和判定稍大，移速稍低，火力更猛。
- **Jason（高速战斗机）**：模型和判定稍小，移速大幅提高，单发伤害降低，攻击频率大幅提高。

满伤 DPS = 射速 × 该档子弹数 × 单发伤害。三档子弹数仍是 1 / 2 / 3，弹道形状先共用（见第 8 章）。

- `WEAPONS` 的火神档位继续描述弹道形状（单发、双发、三发夹角）。Eagle 的 `rate` / `damage` 字段保持 5 和 2，现有 `weaponLevel` 测试不用改。

- 火神伤害用现成的 `emitWithDamage` 盖上 `ShipDef.bulletDamage`。武器测试的 P伤 仍优先于机体。T 的伤害继续走 `HOMING_DAMAGE`，武器测试的 T伤 仍只盖 T。
- 僚机仍走原始发射器，不走 P伤 那层包装。伤害参数改为该机的主炮单发；Eagle 传入 2。

## 3. 造型和动画

局内美术沿用现在的做法：几何模型在开机时栅格成 48 色调色板索引，再烘到离屏 canvas。最近邻、整数像素。`GenerateImage` 或其他位图只用来给 Yoan 看方向，不进运行时，不进 `public/`。

三机共用一套侧倾规则（方案 C，雷电 MK-II 那种滚转）：机头始终朝上，近侧翼变大下掠，远侧翼收成细边，左 5 帧由右 5 帧镜像。每架自己的轮廓、喷口和炮口。侧倾拍数仍是 11，`getBankFrameIndex` 不用按机型分叉。

配色停在玩家组：白、青、淡蓝，加上中性灰。敌机的暗红只给 Eagle 现有的那条红脊；新机不要再借敌方红色当主色，避免和红边敌机糊在一起。

## 4. 选机流程

选机是画布浮层，风格参考合金弹头 1–3：有演出、有名字、有特性，而不是现在难度列表那种四行按钮。打开时暂停标题后面的 attract，和难度浮层一样。调试面板本身仍不暂停；盖上选机浮层之后暂停。

### 4.1 放在难度之后

建议：**选机是进战斗前的最后一步，排在难度之后。** 待确认。

合金弹头 2 / 3 是先定任务，再定人，然后开战。本游戏的难度和关卡是「打什么」，机体是「用什么打」。选机收在进战前，返回链也只在现有步骤后面多一截：改难度不用重看选机，改机体不用重选难度。

另一选项写在第 8 章：选机放在最前。确认前按「难度之后」写流程。

### 4.2 进战路径

```
标题
 ├─ 开始游戏 → 难度(简单/中等/困难) → 选机 → 战斗  battleEntry=stage, t=0
 ├─ Boss连战 → 难度(简单/中等/困难) → 选机 → 战斗  bossRush, 从 Boss 1
 └─ 设置（不选机）

调试面板（右上角热区）
 ├─ 关卡选择 → 关卡列表 → 难度 → 选机 → 战斗
 ├─ 挑战 Boss → Boss 列表 → 普通/困难 → 选机 → 战斗
 ├─ 武器测试 → 选机 → 武器测试（仍走 Easy 数值，不加难度步）
 ├─ 地图预览 → 地图列表 → 预览（固定 Eagle，不选机）
 └─ 调试模式开关（不进战斗）

attract：标题 enter 里启动，固定 Eagle，不选机，保持静音
```

必须先选机才进战斗的入口：标题「开始游戏」、标题「Boss连战」、调试「关卡选择」、调试「挑战 Boss」、调试「武器测试」。

地图预览建议不选机，固定 Eagle。这个模式只卷地图，没有敌人、建筑和武器差别，多一步选机会把地图检查和机体检查绑在一起。

attract 建议不选机，固定 Eagle。演示在 `title.enter` 里自己跑，不能等选机。它是已经签过的第一关演示，换模或换速会改 `battle.replay.test.ts` / `battle.render.test.ts` 的 digest。

### 4.3 返回

和现有选择浮层一样，`menuBack` 等于点返回。

| 从 | 返回到 | 保留 |
|---|---|---|
| 选机 | 打开它的上一步：正式难度、关卡难度、挑战 Boss 的普通/困难、或调试面板（武器测试） | 上一步已经选好的难度、关卡、Boss |
| 难度 | 维持现状：标题，或关卡列表，或挑战 Boss 的阶段列表 | 不经过选机 |
| 关卡列表 / Boss 列表 | 维持现状：回到调试面板 | |
| 选机里左右换机体 | 留在选机 | 高亮的那一架 |

从标题进「开始游戏」再返回，停在标题菜单，不进战斗。调试路径返回到调试面板，attract 在选机关掉之后继续。

### 4.4 交接、Retry、沿用

机体写在 `SceneContext.shipId` 上，和难度一样只活在这一轮，不进设置存档。

| 情况 | 建议 |
|---|---|
| 关卡交接黑卡（第 1→2→3→4 关，以及 Boss连战的下一架 Boss） | 不重新选机。黑卡只显示下一关标题。`shipId` 留在场景上下文里 |
| 结算「再来一次」、Game Over「重新开始」 | 不重新选机。现有逻辑直接 `return 'battle'`，难度和关卡都留着，机体一并留下。重开的是这一关 / 当前 Boss，加载和命数按现有规则重置 |
| 暂停「返回标题」、打完回标题 | `title.enter` 删掉 `shipId`。下一次从菜单进战会再打开选机 |
| 吸引模式、地图预览 | 不读 `shipId`，固定 Eagle |

`carriedRun` 继续只带分数、命、炸弹、死亡、主副武器、僚机等级和延命线。机体不是会随死亡重置的装载，不塞进这份被战斗 enter 消费掉的结构。

Boss连战的 `maxOut` 仍把主炮钉在 Lv3，弹量规则不变。第 4 关弹射、重生飞入、胜利飞离都走现有路径，只是换成选中的模型和喷口。挑战 Boss「4」和地图预览仍不播弹射。

默认高亮 Eagle，确认键可以直接进。待确认。

## 5. 数据架构草案

写法对齐 `WEAPONS` 和 `ENEMY_DEFS`：一行一架，战斗代码不按机型写分支。

```ts
type ShipId = 'eagle' | 'mandy' | 'jason';

interface ShipDef {
  id: ShipId;
  name: string;       // 选机标题
  role: string;       // 一行身份，如「轰炸机」
  blurb: string;      // 两行特性
  speed: number;
  hitRadius: number;
  spriteW: number;
  spriteH: number;
  fireRate: number;   // 火神射速
  bulletDamage: number;
  muzzleY: number;
  mateOffsetX: number;
  flame: { baseLength: number; baseWidth: number };
  // 精灵表和 11 帧喷口由美术模块按 id 注册，不塞进这行数值
}
```

建议落点（接线阶段才建文件）：

| 块 | 落点 |
|---|---|
| 注册表 | `src/game/entities/shipDefs.ts`（或 `systems/ships.ts`）。`SHIPS`、`DEFAULT_SHIP = 'eagle'`、`shipDef(id)`。未知 id 当 Eagle |
| 精灵 | `art/playerSprite.ts` 拆成按 id 取表。Eagle 的现有函数保持原输出，供预览脚本 `scripts/render-player-preview.ts` 继续用 |
| 场景 | `SceneContext.shipId?: ShipId`。省略 = Eagle。不进 `dianlei.settings.v1` |
| 携带 | 不写入 `CarriedRun` |
| 战斗 | `steerPlayer` 读 `speed`；碰撞读 `hitRadius`（默认参数仍是 2.5）；`drawShip` 按 id 取 11 帧；火神时钟和伤害按 §2.2 |

### 5.1 Replay digest

`scenes/battle.replay.test.ts` 的玩法 digest 含有机体坐标、子弹、分数、命数，不含机体 id。`scenes/battle.render.test.ts` 的绘制 digest 含有画了哪张图、画在哪。
