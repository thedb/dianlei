### 1.2 衔接为什么怪

1. **出弹前重后空，再叠一段静默并轨。** 多数式样在前 3 秒内打完，空 1.6–3.5 秒，然后并轨 1.9 秒（左↔右 3.8 秒）全程停火。一轮 6.7 秒里常有 3.5–5 秒没有新弹。玩家体感是「打一下、停很久、换个地方、换个完全不相干的东西再打一下」。
2. **下一式不可读。** 武器由「这条轨第几次停稳的奇偶」决定，这个数是隐藏状态。目标轨又是随机的。HUD 只显示「换轨 x.x」倒计时。到站之后没有任何起手动作，第一发就是答案。
3. **同一条轨的两式没有共同主题。** 左轨是扫射和弹墙，右轨是地面圈和车体冲撞。玩家无法形成「左轨 = 什么」的记忆，只能逐窗硬背。
4. **有两式发射源在画面外或不在车上。** 封轨弹墙从上沿出现。落弹雨的圈落在玩家附近，和列车无关。专文要求「贴车辆两侧，禁止凭空」，但只写给了高射扇。
5. **右 B 前半是空槽，后半是突袭。** 主血 >50% 时右轨偶数次停稳整窗不出手。≤50% 之后忽然 0.12 秒冲到底，没有任何提示。同一个槽，前半太松，后半不公平。
6. **节奏规则零碎。** 「除高射扇外间隔 ×2/3」让各式拍子不对齐，6 式之间没有一套共同的节拍。

## 2. 目标手感

**一句话：铁堡是一列压在三条轨上的地面列车。它用「哪条道危险」逼你横移、换道、躲车身，而不是用满屏弹花逼你微操。**

| | 铁堡（第 2 关） | 炉心（第 3 关） | 黑曜（第 4 关） |
|---|---|---|---|
| 位置 | 地面，三条固定轨，停稳才输出 | 浮台，原地慢漂移 | 空中，三个歇点之间折线飞 |
| 压力来源 | **纵向道**：轨面、车身、相邻轨。车身本身是武器（冲轨） | **旋转与开合**：炮舱绕场转，花瓣开合控制输出窗口 | **瞄准与速度**：单机全身可打，靠机动和快弹 |
| 玩家在想 | 「哪条道现在安全？车要不要冲下来？」 | 「哪个炮舱亮着？花瓣什么时候开？」 | 「它下一个歇点在哪？」 |
| 读招依据 | 车身上的像素动作（枪口、炮门、尾灯、后坐） | 部件状态（亮环、开合） | 机体姿态 |

所以铁堡的 6 式要满足三条：

1. 每一发都从车上某个看得见的位置出来（两侧枪口、车顶炮座、导弹管、尾梁）。
2. 每条轨有自己的主题，A / B 是同一主题的两种变化。
3. 6 式共用一套节拍（§3.1），到站后先亮招再开火，离站前先收枪。

## 3. 新 6 式

### 3.1 共用节拍（锁定建议）

输出窗口仍是 4.8 秒。所有新式样都按同一张拍子排：

| 段 | 时刻 | 内容 |
|---|---|---|
| 起手 | 0 – 0.4 秒 | 到站后亮招（每式一个车身像素动作，见各式「读法」）。不出弹 |
| 拍 1 / 拍 2 / 拍 3 | 约 0.5 / 2.0 / 3.5 秒 | 每拍出弹不超过约 0.9 秒 |
| 收枪 | 最后出弹 ≤ 4.2 秒 | 留 ≥ 0.6 秒空白，然后并轨 |

- 起手只说明「这一站打什么」，在到站之后才出现，**不预告下一条轨**，和专文 §5「目标轨不预告」不冲突。
- 拍距 1.5 秒，三拍铺满窗口，取代「两波前置 + 长空档」。
- 新表直接写最终秒数，不再套 `TIEBAO_RATE_SCALE`。
- 已经飞出的敌弹在并轨期间照常飞，这段 1.9 / 3.8 秒就是给玩家清场的喘息，不另加武器。

### 3.3 侧舷扇扫（左 A，保留）

保留侧舷扫射的手感，只改两处：拍子铺到三拍；到站先亮招。

| 项 | 草案 |
|---|---|
| 枪口 | 末节（`visibleMuzzleRow`）左右边 ±18（`TIEBAO_SIDE_MUZZLE_X`），走岔跟该节转角。不变 |
| 扫法 | 左枪从左下 40° 扫到正下偏右 15°，右枪镜像。不变 |

| 次数 | 3 扫，起点 0.5 / 2.0 / 3.5 秒（原 0.23 / 1.30 / 2.37） |

### 3.4 舷炮排射（左 B，新建，取代封轨弹墙）

旧封轨弹墙的问题是简单、凭空。新式样保留「侧舷」主题，换成从车身发出的斜线排射。

| 项 | 草案 |
|---|---|
| 发射节 | 车心屏幕 y 在 0–400 之间的可见各节，最多取最靠车尾的 3 节。剥厢后节数自然变化 |
| 顺序 | 从前节到车尾依次开火，节与节间隔 0.1 秒，像一排舷炮依次齐射 |
| 每节 | 左右两侧各打 3 发小弹，间隔 0.05 秒，朝外下方固定角 |
| 角度 | 三排依次 40° / 60° / 40°（离正下方的夹角）。不瞄准 |
| 速度 | 110 像素/秒 |
| 尾梁点射 | 每排结束时尾梁中线打 1 发瞄准小弹（`AIMED_MIN_DIST` 规则照旧），车底不是绝对安全 |
| 次数 | 3 排，起点 0.5 / 2.0 / 3.5 秒 |
| 弹量 | 最多 3 节 × 2 侧 × 3 发 × 3 排 + 3 = 57 |
| 起手 | 0–0.4 秒可见各节侧面炮门从前往后依次亮一格 |

在左轨（x = 72）上，左侧斜线很快出屏，右侧斜线斜穿整个屏幕。这是有意的：左轨的压力偏向屏幕中右，和左 A 扇扫配成「扇面赶出去 / 斜线逼回来」。

### 3.5 炮塔追扫（中 A，开场式，改造自高射扇）

旧高射扇一窗四把孤立的五发扇，站定小步就能躲，两门顶炮交替在前半也看不出来。新式样仍出自车顶炮，改成「炮塔转着追人扫」，这是地面装甲目标最典型的读法。它是开场第一式，强度刻意放低。

| 项 | 草案 |
|---|---|
| 枪口 | 车顶炮座：顶炮屏幕 y > 8 时用该门顶炮，两门按拍交替；在画面外时用可见节的炮座（车身中线上的那座）。不在车外凭空生成 |
| 弹流 | 每扫 10 发小弹，间隔 0.07 秒（约 0.63 秒） |
| 追踪 | 第一发瞄准玩家；之后炮口朝玩家转，转速上限 45°/秒。玩家持续横移，弹流会被甩在身后 |
| 速度 | 120 像素/秒 |
| 收尾扇 | 每扫结束后 0.07 秒，从玩家那一侧的侧舷枪口（±18）补一把三发小扇，张角 30°，瞄准玩家。保留旧高射扇「扇」的手感 |
| 次数 | 3 扫，起点 0.5 / 2.0 / 3.5 秒。最后一把收尾扇约在 4.2 秒 |
| 弹量 | (10 + 3) × 3 = 39 |
| 起手 | 0–0.4 秒炮座红点亮、炮口口焰预热 |
| 炮塔被毁 | 仍然射击（沿用旧高射扇规则），座圈破开 |

### 3.6 双联散射 + 追踪导弹（中 B，新建，吸收导弹齐射）

Yoan 指定加入。放在中轨 B，替换旧导弹齐射：中轨的主题本来就是「车顶炮 + 导弹」，导弹留在原位不打乱玩家已有的印象。

| 项 | 草案 |
|---|---|
| 双联 | 一组 = 三个方向（中间瞄准玩家，左右各偏 16°）× 每方向两发并排（垂直于弹道相距 8 像素）= 6 发小弹 |
| 枪口 | 可见节的一侧枪口（±18），一组左、一组右交替。双联的两发都从这一侧枪口两旁 ±4 出来 |
| 速度 | 120 像素/秒 |
| 拍 | 每拍 3 组，组间 0.2 秒。三拍起点 0.5 / 2.0 / 3.5 秒。一窗 54 发 |
| 导弹 | 1.25 秒、2.75 秒各一对，从导弹管 ±28 发出，两发间隔 0.08 秒。追踪 0.55 秒后直线，88 像素/秒（沿用旧值）。一窗 4 发 |
| 起手 | 0–0.4 秒可见节双管口焰亮 + 导弹管盖翻开（2 像素由暗变亮） |

和左 A 扇扫怎么衔接（Yoan 问的）：

- 节拍相同：两式都是 0.5 / 2.0 / 3.5 三拍，换过来以后节奏不跳。
- 空间互补：扇扫是「面」，把玩家推离车底、推到车外侧；双联是「点」，瞄准玩家此刻的位置。
- 常见顺序是左 A → 中 B（左到中是邻轨，1.9 秒）。扇扫最后一扫在 4.17 秒结束，走岔期间余弹下落。到中轨后 0.4 秒起手，0.5 秒第一组双联瞄准刚被扇扫推出去的玩家，1.25 秒导弹再把人逼离那个位置。读起来是「推出去 → 钉住 → 逼走」一条线。
- 反过来中 B → 左 A：导弹在走岔期间继续飞（不清弹），到左轨后扇扫从车两侧向外扫，玩家刚躲完导弹又要躲扇面。这一段压力偏高，所以左 A 的第一扫放在 0.5 秒，不提前。

### 3.7 尾抛轨雷（右 A，新建，取代落弹雨）

旧落弹雨的问题是圈子跟着玩家，与轨道、车身无关，而且 B 不清。新式样把「地面危险」绑到轨面上，并从车尾看得见地抛出来。

| 项 | 草案 |
|---|---|
| 抛出 | 从尾梁中间抛出，0.45 秒弧线（沿用落弹雨那条抛射线的画法）。空中不致命 |
| 落点 | 目标轨的轨面上，y = 尾梁 y + 48；同一抛落两颗，纵向隔 32 |
| 第 1、3 抛 | 落另外两条轨（每条两颗） |
| 第 2 抛 | 落本轨，在车尾正后方（两颗） |
| 下滑 | 落地后成为敌弹（大弹 12×12 判定），沿该轨 X 以 80 像素/秒下滑。地图卷动是 40，雷比地面快，读作「滚下来」 |
| 引信 | 落地 1.2 秒后横爆：最后 0.3 秒闪烁，然后变成左右各 1 发小弹，水平 72 像素/秒 |
| 时刻 | 三抛 0.4 / 1.7 / 3.0 秒。最后一次横爆 3.0 + 0.45 + 1.2 = 4.65 秒，仍在输出窗口内 |
| 弹量 | 10 颗雷 + 20 发横爆弹 |
| 清弹 | 雷和横爆弹都是普通敌弹：B 炸弹清；玩家被击落清；剥厢、阶段切换、死亡不清 |
| 起手 | 0–0.4 秒尾梁抛射口亮，一颗雷在尾梁上露头 |

读法上：雷在轨上时，轨与轨之间的空地安全；横爆的一瞬，空地被横穿。玩家要在「待在轨间」和「横爆前离开横线」之间选。第 2 抛落在本轨，让玩家在右轨先学到「车后这条道会被封」，之后右 B 冲轨就不是突然的规则。

### 3.8 冲轨撞击（右 B，保留，加预警）

| 项 | 草案 |
|---|---|
| 启动 | 进入该式 0.4 秒（原 0.35） |
| 预警 | **0.9 秒**（原 0）。读法见 §4 |
| 下冲 | 0.12 秒 ease-out，车体下沿到 y = 640。不变 |
| 到底 | 尾梁撞出一圈火花（代码粒子，无判定） |
| 返回 | 1.9 秒回到当前节数的歇脚中心。不变 |
| 次数 | 一窗 1 次。不变 |
| 时刻 | 预警 0.4–1.3，冲 1.3–1.42，退 1.42–3.32。3.32–4.8 秒不出新弹 |
| 互锁 | 冲轨没结束不开始并轨；剥厢演出没结束不起冲。不变 |

**建议改锁：冲轨从开战就可以真冲，取消「机车+4 之前只占式样」。** 理由：

- 右 B 前半整窗空着，是「衔接怪」的主要来源之一。
- 原来不冲的理由是 9 节车列 840 高，冲下去会铺满屏幕。但它只铺满**一条道**（判定宽 80，右轨是 x 248–328），而且有 0.9 秒预警，玩家横移一条道就安全。
- 冲轨本来就可受伤，长车列冲下来，可见节变多，玩家还能多打几枪。

若坚持旧锁：机车+4 之前右 B 改打「半冲」，同样 0.9 秒预警，尾梁只下探 96 像素再退回，预警读法照常教给玩家；机车+4 之后才冲到底。

## 4. 右侧冲轨的 0.9 秒预警

要求：俯视像素列车能读懂，不靠字幕，0.8–1.0 秒内明显。

### 4.1 首选：尾灯急闪 + 后坐蓄力 + 车轮火花（全部在车身上）

车尾离玩家最近，开战到终态都在屏幕上（尾梁 y 160–328），是玩家视线最集中的地方。尾梁上的那对黄灯又是车尾唯一的暖色像素。预警全部画在车尾两节上。

| 时刻（预警内） | 尾灯 | 车身 | 火花 |
|---|---|---|---|
| 0 – 0.5 秒 | 4 Hz 闪，黄 → 白 | 整列向上后缩，0 → 6 像素，ease-out | 末两节两侧车轮处，每 0.1 秒 1–2 粒 2×2 调色板橙 / 白火花 |
| 0.5 – 0.85 秒 | 8 Hz 闪，红 ↔ 白 | 保持后缩 6 像素，加 1 像素横向抖动（只抖车，不震屏） | 火花加倍 |
| 0.85 – 0.9 秒 | 白色常亮（定格一拍） | 静止 | 停 |
| 0.9 秒 | 冲 | 0.12 秒冲到底 | 到底撞出一圈火花 |

为什么这样读得懂：

- **后坐蓄力**是最通用的「要冲了」动作。俯视看不到车轮，向后缩 6 像素是看得到的位移，而且方向和冲的方向相反，预备动作清楚。
- **闪烁加速**（4 Hz → 8 Hz → 常亮）告诉玩家「快到了」，不靠读秒。
- **车轮火花**是列车憋劲、轮子打滑的物理读法，只出现在冲轨预警里，不和别的式样共用。
- 色弱玩家看节奏和位移就够，不依赖红色。
- 只在车身上画，不点亮轨面，和专文 §5 / §7.6「不点亮轨道」不冲突。
- 已有底子：`tiebaoTailLampsFlash` 和「同一对尾灯像素加亮」的画法已经在 `art/bossSprite.ts`，只需改节奏和颜色。

可选：配一个合成汽笛音效。只是加分，不能依赖（静音时也要读得懂）。

### 4.2 备选：轨面震线

本轨从尾梁到屏幕底沿，沿钢轨每 16 像素一个 2 像素火花点，0–0.6 秒从车尾一路「跑」到 y = 640，0.6–0.9 秒整条点线闪两下，然后冲。尾灯快闪照留。

- 好处：直接画出冲的路径，最不会误读。
- 代价：等于点亮当前轨。要改专文 §7.6「预告：不点亮当前轨」（这一条在专文里是草案档，不是锁定档）。还要说清楚它只出现在右 B、只画在**当前**轨上，和「换轨不预告目标轨」区分开。
- 建议：先上首选，试玩若仍有人被冲死，再叠加备选的点线。

不采用的读法：字幕、「!!」标记、屏幕边缘红闪、震屏。前两个是文字，后两个不指向哪条道。

## 5. 困难过载三连

**跟着改。** 落弹雨和封轨弹墙退出主战之后，过载不能再引用它们。结构不变：不看分轨表，三式固定循环，每次换轨成功 +1，先打地面压力、最后打导弹。

| 顺序 | 旧 | 新 | 过载加强（草案） |
|---|---|---|---|
| 1（过载开场） | 落弹雨 | **尾抛轨雷** | 三抛每抛都封三条轨（含本轨）；引信 0.9 秒（原 1.2） |
