## 1. 项目概况

《电雷》是竖屏像素飞行射击。实现和 `AGENTS.md` 的约定如下：

- 纯 TypeScript + Canvas 2D。不用游戏引擎。设计文档开头和 §9、§11 仍写着 Taro 4 + React 18；P0（[#1](https://github.com/thedb/dianlei/pull/1)）按当时的要求去掉了 Taro，页面也是 Canvas 绘制，不走 React。
- 外壳两条：Vite H5（`npm run dev` / `npm run build:h5`），以及 `wx-shell/` 微信小游戏壳。`npm run build:wx` 只做类型检查。
- 逻辑分辨率 360×640。固定 60Hz 更新（`FIXED_DT = 1/60`），`requestAnimationFrame` 渲染。最近邻缩放，整数或最接近的倍数，黑边 letterbox，缩放含 `devicePixelRatio`。
- 精灵由代码按 48 色调色板逐像素绘制（`src/game/palette.ts`，`PALETTE_SIZE = 48`），启动时画到离屏 canvas。尾焰、受击闪白、子弹辉光等效果由代码叠加，不画进精灵。
- 可调数值集中在 `src/game/config.ts`。第一关波次在 `src/game/levels/stage1.ts`，并与波次表文档对齐。
- CI（`.github/workflows/ci.yml`）在 PR 和 `main` 上跑 lint、typecheck、test、`build:h5`，并检查 `dist/index.html` 不能出现绝对路径 `/assets`。推到 `main` 后把 H5 传到阿里云 OSS 桶 `it-consultis`、前缀 `vibeCoding/dianlei/h5/`。
- 试玩地址：<https://cdn.it-consultis.com/vibeCoding/dianlei/h5/index.html>  
  哈希脚本在同一前缀的 `h5/assets/`。仓库里没有单独的 `vibeCoding/dianlei/assets/` 目录。`vite.config.ts` 会定义 `__ASSET_BASE__`，默认值指向那个 URL，CI 部署步骤也设置了 `ASSET_BASE_URL`；源码没有引用 `__ASSET_BASE__`。

## 4. 工作流程约定

能从仓库核对的部分：

- 一个里程碑一个 PR。实际对应 [#1](https://github.com/thedb/dianlei/pull/1)、[#3](https://github.com/thedb/dianlei/pull/3)、[#4](https://github.com/thedb/dianlei/pull/4)、[#6](https://github.com/thedb/dianlei/pull/6)、[#7](https://github.com/thedb/dianlei/pull/7)、[#10](https://github.com/thedb/dianlei/pull/10)、[#11](https://github.com/thedb/dianlei/pull/11)。分支名是 `cursor/<里程碑>-<后缀>`（`AGENTS.md`）。
- 代理不自行合并，由人评审后合并（`AGENTS.md`：「Don't merge PRs — user reviews and merges」）。仓库文档没有写「必须听见『合并』两个字才能合」。这条口头口令标为待确认。
- 小修复也各开一个 PR 再合并，不塞进下一个里程碑：[#2](https://github.com/thedb/dianlei/pull/2)、[#5](https://github.com/thedb/dianlei/pull/5)、[#8](https://github.com/thedb/dianlei/pull/8)、[#9](https://github.com/thedb/dianlei/pull/9)、[#12](https://github.com/thedb/dianlei/pull/12)、[#13](https://github.com/thedb/dianlei/pull/13)、[#14](https://github.com/thedb/dianlei/pull/14)。初始提交之后，`main` 上的提交都是这些 PR 的合并，没有看到绕过 PR 的直推。
- CI 门禁是 lint、typecheck、test、`build:h5`，外加相对资源路径检查和 `build:wx` 类型检查。工作流里没有截图任务，也没有云端试玩门禁。多个 PR 正文写明不做截图验收。
- 真机试玩在 CDN 上由负责人做。跟进 PR 引用的是「试玩反馈」「真机请测」「真机反馈」，[#11](https://github.com/thedb/dianlei/pull/11) 和 [#14](https://github.com/thedb/dianlei/pull/14) 点名 Yoan。
